# URL Shortener API Documentation

## Overview

This API provides URL shortening and redirection services. All shortened URLs are stored in Cloudflare KV and can be accessed via simple HTTP redirects. Protected routes require authentication via an API key header. Redirects track click data including IP, timestamp, user agent, and geolocation.

---ma

## Authentication

Protected routes require the `X-Auth-Key` header with your API key.

**Header:**
```
X-Auth-Key: your-api-key
```

**Environment Variable:**
Set `API_KEY` in your `wrangler.jsonc`:
```toml
[env.production]
vars = { API_KEY = "your-secret-key" }
```

## Endpoints

### 1. Verify API Key (Public)

**GET** `/auth/verify`

Verifies if an API key is valid. Rate limited to prevent abuse.

**Headers:**
```
X-Auth-Key: your-api-key
```

**Response:**
- **200** - JSON with validity status
  ```json
  { "valid": true }
  ```
  ```json
  { "valid": false, "error": "Missing X-Auth-Key header" }
  ```
- **429** - Rate limit exceeded
  ```json
  { "error": "Rate limit exceeded" }
  ```

**Rate Limit:** 10 requests per 60 seconds per IP

**Example:**
```bash
curl https://dev.mattr.art/auth/verify \
  -H "X-Auth-Key: your-api-key"

# Response: { "valid": true }
```

### 2. Redirect to URL (Public)

**GET** `/:urlId`

Redirects to the stored URL associated with the given ID and logs click data.

**Parameters:**
- `urlId` (path) - The shortened URL identifier

**Response:**
- **302** - Redirect to the stored URL
- **404** - URL ID not found

**Example:**
```bash
curl -L http://localhost:8787/abc1234
# Redirects to https://example.com
```

---

### 3. Create Shortened URL (Protected)

**POST** `/create`

Creates a new shortened URL mapping.

**Headers:**
```
X-Auth-Key: your-api-key
Content-Type: application/json
```

**Request Body:**
```json
{
  "url": "https://example.com/very/long/path",
  "id": "my-custom-id"  // Optional - auto-generated if omitted
}
```

**Response:**
- **201** - Created successfully
  ```json
  {
    "message": "Created",
    "id": "my-custom-id"
  }
  ```
- **400** - Missing URL or invalid JSON
- **401** - Unauthorized (missing/invalid API key)

**Examples:**

With custom ID:
```bash
curl -X POST http://localhost:8787/create \
  -H "X-Auth-Key: your-api-key" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://example.com", "id": "ex"}'

# Response:
# {"message":"Created","id":"ex"}
```

Auto-generate ID:
```bash
curl -X POST http://localhost:8787/create \
  -H "X-Auth-Key: your-api-key" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://github.com"}'

# Response:
# {"message":"Created","id":"abc7def"}
```

**Note:** URLs without `http://` or `https://` protocol will have `https://` prepended when redirecting.

### 4. Read Shortened URL Data (Public)

**GET** `/read/:urlId`

**Parameters:**
- `urlId` (path) - The shortened URL identifier

**Response:**
- **200** - JSON data
  ```json

    "clicks": [
      {
        "IP": "192.168.1.1",
        "timestamp": "2023-10-01T12:00:00.000Z",
        "userAgent": "Mozilla/5.0...",
        "latitude": "37.7749",
        "longitude": "-122.4194",
        "country": "US",
        "city": "San Francisco",
        "region": "CA",
        "postalCode": "94105",
        "ISP": "Cloudflare"
      }
    ]
  }
  ```
- **404** - URL ID not found

**Example:**
```bash
curl http://localhost:8787/read/abc1234
# Returns JSON with URL and clicks array
```

### 5. Delete Shortened URL (Protected)

**GET** `/delete/:urlId`

Removes a shortened URL from the system.

**Headers:**
```
X-Auth-Key: your-api-key
```

**Parameters:**
- `urlId` (path) - The shortened URL identifier to delete

**Response:**
- **200** - Successfully deleted
- **400** - Missing URL ID
- **401** - Unauthorized (missing/invalid API key)

**Example:**
```bash
curl -X GET http://localhost:8787/delete/ex \
  -H "X-Auth-Key: your-api-key"

# Response: Deleted
```
### 6. List All Shortened URLs (Protected)

**GET** `/read`

Lists all shortened URLs with pagination support.

**Headers:**
```
X-Auth-Key: your-api-key
```

**Query Parameters:**
- `cursor` (optional) - Pagination cursor from previous response
- `limit` (optional) - Results per page, default 10

**Response:**
- **200** - JSON with items array
  ```json
  {
    "items": [
      {
        "id": "abc123",
        "url": "https://example.com",
        "clicks": [
          {
            "IP": "192.168.1.1",
            "timestamp": "2023-10-01T12:00:00.000Z",
            "userAgent": "Mozilla/5.0...",
            "latitude": "37.7749",
            "longitude": "-122.4194",
            "country": "US",
            "city": "San Francisco",
            "region": "CA",
            "postalCode": "94105",
            "ISP": "Cloudflare"
          }
        ]
      }
    ],
    "cursor": "next-page-cursor",
    "hasMore": true
  }
  ```
- **401** - Unauthorized (missing/invalid API key)

**Example:**
```bash
# First page
curl "https://dev.mattr.art/read?limit=10" \
  -H "X-Auth-Key: your-api-key"

# Next page
curl "https://dev.mattr.art/read?cursor=abc123&limit=10" \
  -H "X-Auth-Key: your-api-key"
```

## Error Responses

All errors return plain text with appropriate HTTP status codes:

| Status | Message | Cause |
|--------|---------|-------|
| 400 | Missing url | POST /create without `url` field |
| 400 | Invalid JSON | Malformed JSON in request body |
| 400 | Missing id | GET /delete/:urlId with no ID (shouldn't happen) |
| 401 | Unauthorized | Missing or invalid `X-Auth-Key` header |
| 404 | Key not found | GET /:urlId or /read/:urlId for non-existent shortened URL |
| 500 | Internal Server Error | Server error (check logs) |

## Usage Examples

### Workflow: Create and Use a Shortened URL

1. **Create a shortened URL:**
```bash
API_KEY="my-secret"
curl -X POST https://your-worker.com/create \
  -H "X-Auth-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://very-long-url.example.com/path/to/page"}'

# Response: {"message":"Created","id":"abc123"}
```

2. **Share the short URL:**
```
https://your-worker.com/abc123
```

3. **Users access the short URL:**
```bash
curl -L https://your-worker.com/abc123
# Redirects to https://very-long-url.example.com/path/to/page
```

4. **Check click data:**
```bash
curl https://your-worker.com/read/abc123
# Returns JSON with URL and clicks
```

5. **Delete when no longer needed:**
```bash
API_KEY="my-secret"
curl -X GET https://your-worker.com/delete/abc123 \
  -H "X-Auth-Key: $API_KEY"
```
